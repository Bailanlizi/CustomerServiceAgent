## 排查: .venv 激活失败
- 现象: PowerShell 执行 `.venv\Scripts\activate` 报 `CouldNotAutoLoadModule`(无法加载模块 ".venv")。
- 根因: `.venv` 是被破坏的**跨平台(类 Linux)venv**。目录内仅剩 `pyvenv.cfg` 与一个 `lib64 -> lib` 符号链接,缺失 Windows 必需的 `Scripts/`。`pyvenv.cfg` 中 `home = /usr/local/bin`、`version_info = 3.12.12`(Unix 路径,非 Windows `C:\...`),说明它是用 Linux Python 生成的,在 Windows 上永远不会有 `Scripts\activate`。
- 触发: `.venv` 今天 12:27 被重写(git 无记录,因 `.venv/` 已 gitignore)。项目用 `uv` 管理(uv.lock / uv 0.9.30),且有 Linux 向 CI/Docker(`docker-compose.test.yml`)。最可能来源:在 WSL / 开发容器 / Linux CI 中跑过 `uv venv`/`uv sync`,其 `.venv` 落到了 Windows 路径。
- 修复(未执行,待用户确认):删除损坏 `.venv` 后在本机用 `uv sync` 重建正确 Windows venv;`uv python find 3.12` 本机正确指向 `C:\Users\...\Python312\python.exe`。PowerShell 正确激活写法为 `.venv\Scripts\Activate.ps1`(带 .ps1)。
- 注意: 即使 venv 正常,`.venv\Scripts\activate`(无 .ps1)在 PowerShell 下也可能不稳定,推荐用 `Activate.ps1`。
