## 排查: .venv 激活失败
- 现象: PowerShell 执行 `.venv\Scripts\activate` 报 `CouldNotAutoLoadModule`(无法加载模块 ".venv")。
- 根因: `.venv` 是被破坏的**跨平台(类 Linux)venv**。目录内仅剩 `pyvenv.cfg` 与一个 `lib64 -> lib` 符号链接,缺失 Windows 必需的 `Scripts/`。`pyvenv.cfg` 中 `home = /usr/local/bin`、`version_info = 3.12.12`(Unix 路径,非 Windows `C:\...`),说明它是用 Linux Python 生成的,在 Windows 上永远不会有 `Scripts\activate`。
- 触发: `.venv` 今天 12:27 被重写(git 无记录,因 `.venv/` 已 gitignore)。项目用 `uv` 管理(uv.lock / uv 0.9.30),且有 Linux 向 CI/Docker(`docker-compose.test.yml`)。最可能来源:在 WSL / 开发容器 / Linux CI 中跑过 `uv venv`/`uv sync`,其 `.venv` 落到了 Windows 路径。
- 修复(未执行,待用户确认):删除损坏 `.venv` 后在本机用 `uv sync` 重建正确 Windows venv;`uv python find 3.12` 本机正确指向 `C:\Users\...\Python312\python.exe`。PowerShell 正确激活写法为 `.venv\Scripts\Activate.ps1`(带 .ps1)。
- 注意: 即使 venv 正常,`.venv\Scripts\activate`(无 .ps1)在 PowerShell 下也可能不稳定,推荐用 `Activate.ps1`。

## 退款 FSM 终态短路修复 (Fix 1-4 + 重置脚本)
- 现象: 用户说"我要退款"后机器人直接返回"退款处理中,请稍后查询处理结果"(PROCESSING 状态文本),不再追问订单/原因;管理员端无新审核任务。
- 根因: `app/graph/workflows/refund.py:route_refund_stage` 优先级最高的一行 `if slots.get("refund_submitted_id"): return RefundStage.DONE.value`。上一笔退款若走 `node_submit` 的 ALREADY_EXISTS / 短路路径,会把 `refund_submitted_id` 持久化到 `ConversationSession.working_memory_json`;新一轮"我要退款"直接命中 DONE,子图跳过所有节点,answer 为空,前端只渲染 PROCESSING 状态文本,且根本没调 `submit_refund_application`,自然无 AuditLog。
- 改动:
  - Fix 1 (`app/conversation/state_manager.py:prepare_turn`): 进入 REFUND 域且工作记忆残留 `refund_submitted_id` 时,清理终态字段(refund_submitted_id / user_confirmed / workflow_stage / last_tool_result)。触发条件:`explicit_new_destination` 或强新退款意图前缀("我要退/我想退/申请退/办理退/发起退/退一下/退掉") + 排除状态查询词("进度/状态/多久/怎么样了/编号"),避免"我的退款申请进度怎么样了"被误清。
  - Fix 2 (`app/graph/workflows/refund.py` 三个追问节点): `node_identify_order` / `node_collect_reason` / `node_await_confirmation` 的兜底 `if response` 改为 `if response and getattr(response, "content", "")`,防止 LLM 返回空 content 时 answer 为空。
  - Fix 3 (`app/graph/workflows/refund.py:refund_subgraph_entry`): DONE / REJECTED 终态写入兜底文案(若有 submitted_id 则提示"已有申请 #X";否则"当前退款流程已结束")。
  - Fix 4 (`app/api/v1/chat.py`): 新增 `_refund_placeholder_answer(values)` 按 workflow_stage 派生占位;REFUND 域 answer 为空时也写入 assistant 消息,保持历史连续。
- 测试 (`test/test_refund_state_reset.py`, 13 用例): 覆盖 prepare_turn 清/不清终态、状态查询不被误清、LLM 空 content 兜底、子图终态兜底 answer、占位派生。新增 + 现有退款相关共 44 通过。
- 重置脚本 (`scripts/reset_refund_state.py`):
  - 默认: 重置该用户 ConversationSession.working_memory_json 为 defaults。
  - `--wipe-refunds`: 同时删除该用户 RefundApplication + AuditLog(需二次确认)。
  - `--dry-run`: 只打印不动库;`--yes`: 跳过交互确认。
  - 注意: 重置 session 后前端 BrowserState 仍持有旧 conversation_id,需 Ctrl+Shift+R 或切无痕触发新 session。
