## Agent 端到端测量方案（草稿 v1 已交付，未动代码）

用户提供了一个**用于 Agent 能力评估的六维指标清单**（成功率 / 工具调用准确率 / 进度率 / 推理质量 / 效率 / 稳定性），询问本项目最该补哪一项。

**判断结论**：本项目只补 ① 任务成功率 + ② 工具调用准确率（含选择+参数），其余四项不做（理由详见对话）。理由：
- 本项目架构是「Thin Orchestrator + 子图 FSM」，**没有显式 planner**，所以 PlanQuality / PlanAdherence 是空指标
- 不部署、不计成本，所以效率/Token 优化不是面试卖点
- LLM 非确定性是常识，10 次 σ 时间不值

随后用户明确表示："先不要动代码，先把你的测量方案给我看看"。

**交付内容**（见对话正文方案草稿 v1）：
1. 三层测量目标：任务成功率 / 工具调用准确率 / Trace 节点耗时+Token
2. 12 个核心场景设计（订单查询 / 退款全流程 / 政策咨询 / 越权 / 幂等 / 重登恢复 / 空 session 等）
3. Trace 方案选择：自建 LangChain Callback（零依赖）优于 LangSmith trace-only（上云受限）
4. 脚本结构设计：`scripts/eval_agent_e2e.py` 模块拆分 + JSON 输出 schema
5. 风险与边界诚实标注（含业界无统一基准这一条）
6. 时间预算：5h 完整版 / 3h 砍到 8 场景精简版
7. **6 个待用户拍板的决策点**（场景数量、期望链定法、跑几次、安全拦截计入方式、输出位置、trace 维度）
