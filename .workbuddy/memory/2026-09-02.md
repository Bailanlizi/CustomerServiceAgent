## RAGAS 评估 TimeoutError 诊断（只读，未改代码）

**现象**：跑 baseline 的 RAGAS 评估，每个 judge 请求约 60 秒后抛 `TimeoutError()`，进度条 1/30 卡死。

**根因（已定位，有实测证据）**：`.env` 里 `JUDGE_LLM_MODEL = deepseek-v4-pro` 是**推理型模型**（带思维链 reasoning）。作为 RAGAS judge 时，每个请求先做思维链推理，reasoning token 数不可控：

- 实测（同一个 NLI judge prompt）：
  - `deepseek-v4-flash`：1.4s，reasoning_tokens=49（几乎不推理，稳定）
  - `deepseek-v4-pro`：3.0~10.9s，reasoning_tokens=171~503（波动大，不可控）
- RAGAS 真实 judge prompt 更长（完整 context + 多个 statements），pro 的 reasoning 会爆炸，单请求超 60s → 触发超时（deepseek 推理 API 网关约 60s 硬超时）。
- RAGAS 配的 `RunConfig(timeout=120)` 是每题每指标总超时（`asyncio.wait_for`），但 60s 就超时说明是更底层的服务端超时先触发。

**解法**：judge 任务（NLI verdict 0/1、claim 分解）是确定性判断，不需要推理模型。**换 `deepseek-v4-flash`** 即可：快 10 倍、token 省 90%+（推理模型的 reasoning token 也算钱）。修改点：`.env` 的 `JUDGE_LLM_MODEL`，一处即可，代码不用动。

**关联发现**：之前 `baseline.ragas.json` 里 faithfulness 10/45、factual_correctness 12/45 大量 null，很可能也与 judge 慢/超时有关（不全是中文 claim 提取问题）。

**环境事实**：
- deepseek 账户可用模型：deepseek-v4-flash、deepseek-v4-pro、deepseek-v4-flash-vision-exp。
- judge 已独立配置（`.env` 的 JUDGE_LLM_MODEL / JUDGE_OPENAI_API_KEY / JUDGE_OPENAI_BASE_URL），不再复用业务 LLM_MODEL。
- evaluate_ragas.py 已精简到 2 指标（Faithfulness + FactualCorrectness(mode=precision)），配了中文 prompt（app/evaluation/chinese_ragas_prompts.py），RunConfig(timeout=120, max_retries=3, max_workers=2)。
- 项目 venv 路径：`.venv/Scripts/python.exe`（import ragas 需先做 langchain_community.chat_models.vertexai 兼容 hack）。

## 更正：换 flash 无效，真正的根因是 DeepSeek V4 默认开启 thinking

**结论反转**：上文"换 deepseek-v4-flash 即可"是**错的**。用户换了 flash 仍 timeout。实测排查后定位真正根因并已修复。

**真根因**：DeepSeek V4 的**思维链（thinking）是请求参数，不是模型差异**——`deepseek-v4-flash` 和 `v4-pro` **都默认开启 thinking**（连简单 prompt 都返回 `reasoning_content`）。RAGAS 的结构化 JSON 输出 prompt 会触发 reasoning 模型生成数百 reasoning tokens，单次调用从 <1s 暴涨且波动巨大。

实测（同一条结构化长 prompt）：
- thinking 默认开启：1.9s / 4.0s（reasoning_tokens=177 / 464，波动大）；真实 statement prompt 达 9.8~27.2s
- `thinking: {"type":"disabled"}`：0.6~0.8s（稳定）

RAGAS 每题 4 次这类调用（statement 生成 + NLI + claim 分解 + NLI），撞上波动就累计超过 `RunConfig(timeout=120)` 的 `asyncio.wait_for` → 全部 TimeoutError。

**修复（已改，1 处）**：`scripts/evaluate_ragas.py` 的 judge `ChatOpenAI` 加 `extra_body={"thinking": {"type": "disabled"}}`（ChatOpenAI 有 extra_body 字段，自定义参数用 extra_body 而非 model_kwargs）。

**验证**：修复前 `--limit 3` 的 6 个 job 全部 120s 超时（>4 分钟被 SIGTERM）；修复后 6 job 18s 完成，faithfulness/factual_correctness(mode=precision) 均有值、无 null。

**关键知识点**（供后续）：DeepSeek V4 思维模式三档 = `thinking:{type:"disabled"}`（非思维，最快）/ `thinking:{type:"enabled"}+reasoning_effort:"high"`（默认）/ `reasoning_effort:"max"`（思维-max）。judge 这类确定性判断必须禁用 thinking。旧模型名 deepseek-chat/deepseek-reasoner 已于 2026-07-24 退役，现分别指向 v4-flash 非思维/思维模式。
