## 项目定位确认（重要方向校准）
- 用户明确：CustomerServiceAgent（本工作区，Python 电商客服 Agent 项目）的求职定位是 **AI 应用 / Agent 开发方向**，作为主作品打磨（区别于 memory 中 GreenLoop/campus-trade-api 那个 Java 清结算项目）。
- 因此评价/改造的优先级需围绕「Agent 核心能力」展开，而非「金融正确性」。

## 项目代码盘点（只读分析结论）
- 技术栈：FastAPI + LangGraph + SQLModel + PostgreSQL(pgvector) + Redis + Celery + Gradio，LLM 走通义千问（Qwen）。
- 已有亮点：LangGraph 显式图（意图路由→订单/政策/退货→生成）、Redis checkpointer、RAG（余弦相似度+0.5 硬阈值）、人工审核（Human-in-the-loop 雏形）、SSE 流式、Celery 异步。
- 关键缺口：
  1. `graph/tools.py` 的 3 个 @tool + refund_tools 列表是死代码，workflow 未接入；且与 `nodes.py` 的 `check_refund_eligibility` 同名不同签名。
  2. 退货逻辑三套并存（nodes.handle_refund / services.RefundEligibilityChecker / tools），真源不唯一，规则不一致（nodes 允许 PAID 状态退货，service 只允许 SHIPPED/DELIVERED）。
  3. 意图识别用裸字符串 strip+容错，未用 with_structured_output。
  4. 无 Agent 评测（eval）、无可观测性（tracing）。
  5. 金额用 float（Agent 方向降级为加分项，非核心）。

## 改造方向共识（Agent 方向优先级）
- P0：tool-calling 真正落地（ToolNode + bind_tools）、意图识别结构化输出（Pydantic + with_structured_output）、建 Agent 评测集。
- P1：Human-in-the-loop 升级（通用 interrupt/确认机制）、RAG 增强（rerank/query 改写/多路召回）、可观测性（LangSmith/LangFuse）。
- P2：多 Agent 协作、长期记忆/用户画像。
- 叙事主线：从「电商客服系统」升维为「通用 Agent 编排能力」。
