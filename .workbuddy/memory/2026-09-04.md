## 根因与修复

### 错1：Redis JSON.SET 失败
- 根因：localhost:6379 实际跑的是 Windows 原生老旧 redis **3.0.504（PID 5968）**，
  无 ReJSON 模块；docker 的 `ecommerce_redis`（redis-stack-server，带 ReJSON）被它抢占 6379。
- 修复（非破坏性，不动老 redis）：
  - `docker-compose.yaml`：redis 发布端口 `6379:6379` → `6380:6379`
  - `.env`：`REDIS_PORT=6379` → `6380`
  - 实测 `JSON.SET @6380` 成功。

### 错2：refund_applications 表缺失
- 根因：`app/models/refund.py` 定义了该表，但 5 个迁移文件无一创建它（模型-迁移脱节）。
  `alembic/env.py` 已 import RefundApplication 进 metadata，故可 autogenerate。
- 修复：`alembic revision --autogenerate -m "add_refund_applications"` 生成
  `migrations/versions/6a81cd1a4aba_add_refund_applications.py`（仅建表+3索引），
  已 `alembic upgrade head` 应用，表已存在。

### 错3（验证中发现的连带 bug）：政策答案发不出 + intent JSON 泄露
- 根因：`chat.py` 用 `token_sent` 标志门控政策答案下发；`intent_router` 的结构化输出
  token 流被当成普通 token 设了 `token_sent=True`，导致政策答案被 `if fallback_answer and not token_sent` 吞掉；
  同时 intent 的 `{"intent":"POLICY"}` 被泄露给前端。
- 修复：新增 `INTERNAL_LLM_TAG="internal_llm"`（`policy_answer_guard.py`），
  用 `.with_config({"tags":[...]})` 固化进 `intent_classifier` 与 `policy_answer_llm`；
  `chat.py` 对带 `POLICY_GUARD_TAG` 或 `INTERNAL_LLM_TAG` 的流事件直接丢弃。
  注：`.with_config` 比 `ainvoke(config=...)` 可靠——后者在 LangGraph 节点内标签不一定冒泡到 astream_events。
- 验证（临时 8001 实例跑通）：政策咨询返回完整答案且无 intent 泄露；订单查询流式正常（无回归）。

## 错4：Error while searching: No such index checkpoint_write
- 现象：单轮问答正常，但「同一会话线程的第二条消息」报 `No such index checkpoint_write`
  （用户连发「内衣能退吗」+「我要退 SN20240004」触发）。
- 根因：`AsyncRedisSaver` 依赖 Redis 的 `checkpoint` / `checkpoint_write` 两个搜索索引；
  包内源码 `setup()` 注释明确写 "It MUST be called before using the checkpointer"。
  而 `compile_app_graph()` 只 new 了 saver 就直接 compile，**从未建索引**。
  写入能成功（不依赖索引），但读取/搜索历史 checkpoint 需要索引 → 第二轮才炸。
- 修复（`app/graph/workflow.py`）：compile 前加 `await checkpointer.asetup()`
  （`asetup()` 创建两个索引，`create(overwrite=False)` 幂等，重复启动安全）。
  顺带清理该文件：删除未使用的 `import redis.asyncio as redis`，import 排序（ruff 现已全通过）。
- 验证（临时 8001 实例）：政策轮正常；同线程续问退货 → 「帮您提交退货申请。」
  索引错误消失，退货链路端到端跑通。回归测试 15 passed。
- 注意：此修复同样需要用户重启 8000 的 uvicorn 才生效。

## 错5：第三轮重复回答前两轮的问题（跨意图历史污染）
- 现象：连问「我的订单到哪了？」→「内衣拆封了能退吗？」→「我要退 SN20240004」，
  第三轮回答变成「针对您的三个问题，回复如下：…」，且用售后身份重新答了前两问。
  用户怀疑是 prompt 设置问题——**不是**，是会话状态结构坏了。
- 根因（已用真实图三轮复现坐实，checkpoint messages 直接取证）：
  `generate` 节点（ORDER / POLICY 路径）只返回 `answer`，**从不把 AI 回复写回 `state["messages"]`**；
  而 `messages` 是 `Annotated[list, operator.add]` 经 checkpoint 跨轮累积，`chat.py` 每轮都注入本轮 Human。
  于是第 3 轮 refund_agent 拿到 `[H1, H2, H3]` 三条连续 Human、中间零条 AI →
  模型认为三条都还没回，就一起答了（且用 REFUND_AGENT_PROMPT 的售后身份重答 Q1）。
- 修复（`app/graph/nodes.py`，三处）：
  1. `generate` 两个分支均回写 `AIMessage(content=answer)` 到 messages（核心，保证 Human/AI 交替）；
  2. 新增 `select_refund_context_messages()` + `MAX_REFUND_HISTORY_TURNS=3`：
     退款 Agent 只带最近 3 轮，且窗口起点固定为 `HumanMessage`
     （否则会拆开 `AIMessage(tool_calls)` 与 `ToolMessage` 配对，触发模型 API 400）；
  3. `REFUND_AGENT_PROMPT` 加「只回答最新一条消息 / 不越权答非售后问题」（第三道防线，治标）。
- 验证：六轮真实图复现（订单→政策→政策→政策→退款追问→退款补原因）：
  前四轮各自单独作答；第 5 轮只索要退货原因不复述旧问；第 6 轮正确调工具并保留退款流程上下文
  （拿到 SN20240001 + 原因，工具返回「含运动内衣不可退」，模型给出解释）。
- 测试：新增 `test/test_conversation_history.py`（6 用例，覆盖窗口裁剪/tool配对/AI回写/退款Agent窗口）。
  相关测试 21 passed，ruff 全通过。README 已补「多轮会话历史的一致性」章节。
- 注：复现脚本 thread 必须每次换新的，旧线程历史已被污染。

## 复用结论（补充）
- LangGraph Redis checkpointer：新建 `AsyncRedisSaver` 后必须 `await asetup()` 建索引，
  否则首次「读历史/多轮」会以 No such index 失败——且单轮测试不会暴露，必须测同 thread_id 多轮。
- 反复启停 uvicorn 可能触发 `asyncpg InterfaceError: connection is closed`（DB 池失效），
  属测试实例侧问题，干净重启即可，不代表项目 bug。
- **多轮 Agent 排查范式**：凡「前面几轮正常、某轮突然复述/串答」，先看 checkpoint 里 messages 的
  序列结构（Human/AI 是否成对、tool_calls 与 ToolMessage 是否配对），再看 prompt。
  可用 `graph.aget_state(config).values["messages"]` 直接取证。
- 从 Redis 直读 checkpoint 不可行：`channel_values` 是分片存储，读出来为空；
  取证请用 `graph.aget_state(config)`。
